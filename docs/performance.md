# 性能验证方法与开放问题

本文件描述可复用的测量原则，不发布私人项目、设备、工作区、缓存目录或历史产物清单。当前版本的构建和验收范围见 [status.md](status.md)。

## 测量原则

- 固定源码、CLI、Worker、Web 和媒体依赖身份，分别记录冷启动与热运行；只对相同候选复用既有证据。
- 分开测量实际用户操作、原生准备、像素领取、浏览器解码与呈现、音频设备消费。重叠阶段不能相加推算总吞吐，自动化轮询时间不能冒充屏幕延迟。
- 记录首帧、连续帧间隔、音频欠载、定位、暂停与恢复，以及退出后子进程和持久任务状态。
- 对来源图、RGBA 与 PCM 使用独立预期值。预览与导出一致、任务成功或文件可解码都不能单独证明像素和声学质量。
- 保留失败结论及原门槛，不以更宽门槛覆盖旧失败。新版本不得继承未重新确认的整体验收结论。

## 当前实现范围

原生流水线使用有界来源准备、解码与 GPU 资源预算，按固定修订和精确时间产生画面。共享来源验证、固定依赖身份、像素摘要、读取连接及暂存缓冲的复用均保留取消、权限和生命周期检查。客户端连续呈现、来源图和导出仍使用公共应用语义，具体边界见 [architecture.md](architecture.md) 和 [contracts.md](contracts.md)。

## 仍需覆盖的验证

更广的格式与 4K 组合、冷启动、长时间预览、设备切换、故障恢复、物理声画以及跨平台安装仍需独立验收。Apple Silicon 的设备验证已延后至具备相应硬件时进行；Intel 的限定构建或静态检查不替代这些验证。
