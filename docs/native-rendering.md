# 原生渲染替换

目标是直接替换浏览器媒体执行链路。工程格式、公开编辑和渲染入口继续由现有 Rust 应用层定义，不添加产品版本开关、并行旧后端或失败后的隐式回退。当前提交 `74afa429` 保留替换前的性能候选及独立像素失败证据。

## 实现与复用边界

- 现有 composition 编译、时间采样、资源锁和应用执行会话继续负责业务语义。
- 原生 renderer 只接收已准备的像素、几何、混合、蒙版与效果指令；通过原生 wgpu 执行现有固定 WGSL。浏览器 Canvas 的颜色、字形、路径栅格化需要显式适配，不能把相似画面当作等价。
- 原生媒体适配器负责受限解码和音频处理，复用已有 FFmpeg 进程生命周期与授权资源。GPU 输出直接进入 Rust sink 和编码器，不再通过 Playwright/Node 字符串传输。
- 宿主装配实现并保持固定修订、取消、租约、预算和发布围栏。GPU、编解码器及字体的实际身份进入执行证明；历史存储证明保持原样。
- Web 保留编辑和显示职责，预览与导出消费同一原生执行语义。来源图、暂停/seek/恢复、预览缓存和音频设备协议一并接入。

## 依赖边界说明

新增 `opencut-render-worker` 专用宿主进程，仅依赖原生适配器，不解析 CLI 命令或公开工程路径。父进程保留资源授权和发布责任，通过有界二进制管道传输验证字节、采样观察和 RGBA，独立监测 RSS、逐帧/任务期限并终止整个进程组。该进程在一次视频任务中复用 GPU 和解码器。

新增 `opencut-renderer` 原生适配器，依赖纯 `opencut-contracts` 中的几何和效果事实，不依赖应用、存储、CLI 或 Web。`wgpu` 限于该适配器，启用原生 Metal/Vulkan/DX12 与 WGSL，不启用浏览器后端；`pollster` 负责本地设备初始化，`sha2` 记录嵌入着色器身份。依赖基线按这些具体边逐项维护，不重生成允许列表。此模块是最终原生执行层，不是临时第二套业务操作。

同一适配器使用仓库已有的 `tiny-skia` 栅格化已采样的几何路径。独立文字验收发现轮廓填充的抗锯齿与 Canvas 不同，因此文字改由固定 `skia-safe` 的原生 HarfBuzz/Skia 执行；不保留第二套文字后端。使用官方 CPU textlayout 构建及默认 CPU 特性以复用其固定二进制缓存，不启用 Skia GPU，不将附带的 PDF/JPEG 接口暴露为业务操作。字体仅从验证过的字节创建，单一固定字体迭代器与空 fallback manager 拒绝系统替代字形。`ttf-parser` 核对真实字体元数据；中线按 OS/2 字体的 em 比例和 1/64 px 规则归一化。新增依赖边仅位于原生适配器，动画、布局意图、图层顺序、资源选择和字体授权仍由现有 composition/application 准备。

文字适配依据 [Chromium TextMetrics](https://github.com/chromium/chromium/blob/153.0.8010.12/third_party/blink/renderer/core/html/canvas/text_metrics.cc)、[归一化字体度量](https://github.com/chromium/chromium/blob/153.0.8010.12/third_party/blink/renderer/platform/fonts/simple_font_data.cc) 和 [macOS SkFont 配置](https://github.com/chromium/chromium/blob/153.0.8010.12/third_party/blink/renderer/platform/fonts/mac/font_platform_data_mac.mm)。原生实现仍须通过独立 Canvas 像素和布局门槛，不以共用库名称推断等价。执行证明另外记录操作系统构建、架构和字体平台，预览缓存包含这些事实；旧证明按其原始字段读取，不能用当前依赖常量改写历史结果。

默认 Canvas 的空格边界依照 [PlainTextNode 分词整形](https://github.com/chromium/chromium/blob/153.0.8010.12/third_party/blink/renderer/platform/fonts/plain_text_node.cc) 处理：保留词内 kerning，分别整形空格；不能通过全局关闭 kerning 修复词间差异。整行 ICU 双向级别先决定视觉顺序，再划分单词，避免逐词重新推断段落方向。[精确字体度量](https://github.com/chromium/chromium/blob/153.0.8010.12/third_party/blink/renderer/platform/fonts/skia/skia_text_metrics.cc) 使用字形路径边界，并按 Canvas 的定点转换方式调整原生字宽。当前三个文字样例尚不能证明所有 Unicode、复杂脚本、字体合成及平台组合等价，这些仍属于完整文字验收范围。

`opencut-media` 增加固定的 `ffmpeg-next` 绑定，直接使用 libav 的解复用、解码、像素转换和重采样。原生输入只借用已验证字节端口：AVIO 每次同步操作重新绑定当前授权，限制读取块、总读量和截止时间，禁止协议与嵌套文件打开；不会把路径放进公共 DTO，也不把 CLI 当内部 RPC。解码器、相邻帧和 GPU scratch 在同一执行生命周期复用，跨请求授权不复用。

交付包必须携带与验证候选一致的库、配置、哈希、许可证和来源。当前开发机 Homebrew FFmpeg 8.1.2 含 `--enable-gpl`，不能直接据此宣称现有发行包许可和搬迁安装已通过。原生库发行装配采用明确的 LGPL 构建，关闭 GPL/nonfree 组件；编码器仍通过已有原生端口装配。库 ABI 和构建身份属于执行证明，不作为用户可选的产品版本。

现有 WGSL 直接从锁定的 vendor 目录嵌入，保留 LICENSE 和 source.json，不复制或改写来源证明。移除浏览器包前需要将这些运行资产连同许可证移到最终原生资产位置，并验证哈希保持一致。

## 集成和统一验收

连续预览复用同一原生帧会话和 worker。每个播放 owner 保留解码器、GPU 和验证资源缓存，换代、撤权、停止及有界空闲会清理进程。父进程与浏览器各有固定的图片驻留预留，容量不随每帧上报的队列字节数变化；已领取但尚未结束的二进制读取也计入预留。浏览器只校验并显示原生 RGBA；点击检测在图层完成效果和蒙版后读取单个像素 alpha，按真实堆叠顺序返回。

同一受限工作进程协议支持 CPU 文字测量，复用渲染的字体布局实现，测量时不创建设备或整张画布；同一次字幕请求复用进程处理所有 cue，保留授权、期限和驻留限制。公开字幕输入不再接受客户端观察，Web 一次请求即可取得布局和原子编辑计划。内部测量事实位于应用层，具体进程与字体实现留在原生适配器，不新增业务入口或领域依赖。

后续音频接入复用现有应用层采样位置、增益、准备事实、窗口准入和收据校验，原生 DSP 放在 `native-services/native_audio`，不把样本处理移进领域或合成层，不新增依赖边或公开业务入口。SoundTouch 按锁定源码移植，保留 Float32 写入、快速相关搜索、FIFO 历史、未冲刷尾部和实测的 8192 帧离线启动延迟；压缩器及两处不同的重采样按锁定 Chromium 源码适配。完整许可和来源哈希留在 `native-services/vendor/audio`，SoundTouch 衍生部分继续遵守 LGPL-2.1-or-later。

原生导出内部执行器通过现有应用回调取得授权描述符、窗口准入、准备事实和逐块采样位置。独立 PCM 模块只持有实际保留窗口，拒绝把缺少的窗口替换为静音；小音频的 sinc 解码重采样和容器拼接的线性重采样共用已适配的固定 DSP。Codec、待解码起始包及帧在打开前预留工作空间，预留持续到解码器释放，复制到自有 PCM 时同时计算两个所有者；混音按既有存储顺序逐声部写入 Float32，整段峰值门控与连续压缩完成后才选择输出范围。应用的原生收据校验复用同一事实校验，仅要求真实的原生解码身份，不允许将原生结果报告为浏览器执行。这些内部适配模块不引入新依赖、公开操作或第二套时间线编译器。

后续接线已将原生画面与音频的父进程管道、RSS/期限监测、严格 cgroup 装配、进程组回收和运行文件哈希核验提取为 `native_process`，没有新增 crate 依赖或第二套进程生命周期。音频 worker 不初始化 GPU，使用同一可执行文件的私有音频执行协议；授权仍在父应用，PCM 和来源字节按 64 KiB 传输，最多 16 MiB 的类型化采样事实按块发送。窗口索引、声道描述和所有者描述也在 PCM 预算中保留到释放。WAV 与视频导出宿主已接到这一条原生执行路径，已完成集成构建，真实任务及独立 PCM 验收的当前结果见状态记录；实时预览也已完成首轮宿主硬切换，后续传输事实与定位修正正在集中验证。

传输包上限不扩展 sink 准入：来源和 JSON 事实块最多 64 KiB，PCM 每声道每块保持原有 4096 帧上限。该上限由应用 PCM 端口统一声明，原生发送、父进程接收、旧进程适配和 WAV 文件 sink 共用。真实 WAV 导出曾因此拒绝过大原生块，修复及同一真实文件 sink 的回归记录以状态文件为准，不能用宽松内存 sink 的通过替代文件输出验收。

容器拼接消费者选择零时刻之前或对应的独立编码包开始解码，保留短独立音频的原有入口行为。负时间戳包不能先解码再丢弃输出：AAC overlap/PNS 状态会因此不同。选择过程沿用授权 AVIO、包数量、读量和期限边界，不把包时间戳改成工程时间；缺少可用时间戳或独立包时明确拒绝。同一保留 AAC 源的独立解码回归及实际 48k/44.1k/区间 WAV、视频编码前 PCM 已逐样本通过；这不覆盖其它压缩格式或普通实时 PTS 预览。

公开音频证明区分真实原生 worker/编解码库/DSP/系统身份与不可变旧浏览器证明，不提供后端选择或回退。现有工程及算法标签保持精确；旧证明原样读取。逐样本位置和块复用共享 composition Rust 声明的序列化，而非另建采样 DTO。`serde_json/raw_value` 仅用于这些新增的私有浮点增益反序列化，通过原始数值词法和标准正确舍入解析保留每个 f64 位；不切换全局 JSON 浮点解析或改写历史工程数据，不增加依赖包。

DSP 组件已通过 24 组独立 Chromium/SoundTouch PCM 对照，内部导出执行器另通过 28 组独立 PCM 对照及共享来源/修剪/准备/拒绝检查；输入为合成 float32 RIFF/WAV，另一个保留 AAC 容器样例已通过实际宿主逐样本 PCM，不能扩展到其它压缩格式。新 libav 音频端口的六种 PCM 表示、连续读取、原生声道/PTS/EOF、seek 和失效检查已通过。原生画面与音频共用错误转换，保留授权端口的取消、撤权等原始代码，不能改写成存储准入错误。时间窗与拼接语义仍由应用选择。WAV 与视频导出宿主已接入隔离工作进程；独立压缩格式 PCM、生命周期及预览设备消费的验收范围以状态文件为准。

实时预览的后续内部适配共用一个授权 `NativeInput`：打开、读取、重定位和释放均走现有应用资源端口；窗口只报告真实 PTS，不重建工程时钟。普通 PCM 保留有界窗口与一个读取尾块，准备分支共用导出 DSP；重定位保留 demux/AVIO，但重建编解码上下文。扩展模块仍位于 `native-services/native_audio`，不新增 crate 依赖或审核基线豁免。共享 Rust 预览事实新增私有精确反序列化，不改变其现有序列化表示。

原生实时压缩器按声明的整数预读帧提前取样，设备端直放完成的 PCM，不叠加浏览器压缩或同一预读延迟。实际 EOF 后仅补固定 DSP 尾部所需的零值，缺少的界内 PCM 窗口仍是错误；换代或音量覆盖换代重置压缩器状态。首轮集成候选通过 118 项检查与真实授权 HTTP AAC 独立 PCM，原生进程跨暂停、定位和重播复用。后续新增公开只读 `pcm_stage=mastered` 事实并由客户端强制核验，同时修正 Wave 分窗重定位的精确原生采样 PTS；当前候选已完成集中构建、同一程序合同检查、120 项 Rust 检查和实际 AAC HTTP/导出独立 PCM；六组保调变速的 12 组对照逐样本一致。网页有一条续播约 1.87 秒停顿的失败记录，后续多轮成功不能消除这条未解决问题。独立参考覆盖连续压缩、普通 PTS/采样率/变速和六组保调变速；每个原生对照结果仍分别绑定实际候选。物理设备和完整交付未验收。

来源图原生实现位于已有 `native-services/source_art`：流式波形复用原生音频缓冲源重采样内核，明确保留全部声道、128 样本桶和观测 EOF；CPU 图像解码、方向与 JPEG 编码位于已有 renderer raster 适配器，复用已审核的 Skia 依赖。图像执行只消费应用给定的目标尺寸，像素/编解码/其它驻留及有界 JPEG 写入均纳入准入。方向变换使用 Skia 自身的 [encoded origin 定义](https://github.com/google/skia/blob/chrome/m153/include/codec/SkEncodedOrigin.h)。视频轨道的容器 ID、编码尺寸、像素宽高比和旋转仅是观察，不替代工程语义。现已在源码接通私有原生 worker、父进程授权 CAS、取消/期限/RSS 监测和回收围栏，以及唯一宿主装配、缓存与 Web 回执校验。新执行要求真实原生身份，历史不可变浏览器证明保持精确读取。高声道解码帧按驻留块预算借用切片处理，不复制整帧。当前已完成 CLI/worker 集中构建、同一程序合同核对、169 项 Rust 检查与独立波形/JPEG、实际宿主/HTTP/编辑器限定验收；未新增 crate 依赖或修改审核基线。实际编辑器暴露的活动/静态画布重叠已通过 Web 修正及 6 项回归；保留暂停画布但在活动 worker 呈现时隐藏，避免遮住播放。更广格式、长片/4K 性能、旧间歇停顿与完整交付仍开放。

画面退休准入仍由已有 `host-runtime/audio_preview/visual_owner` 持有一个原生执行器。每个会话最多一个请求等待旧画面完成或旧代际退出，等待上限为本次策略期限与一秒的较小值；等待不分配 RGBA、取得 CAS 句柄或启动第二个渲染器。每次检查继续核验授权、owner/lease、generation/overlay 和停止状态，取得执行权后再核验并保留原发布围栏；超额或超时仍返回既有繁忙错误。这是宿主资源生命周期的内部修改，不增加公开合同、依赖或业务入口，当前构建及验收范围见状态记录。
