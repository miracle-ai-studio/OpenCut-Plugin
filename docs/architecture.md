# 架构

OpenCut 是模块化单体。外部 Agent 负责创作规划，编辑系统执行经过授权的读取、计划、事务和媒体任务。

| 层 | 实现 | 职责 |
|---|---|---|
| 领域与时间 | editor-core、time | 精确时间、编辑规则、工程不变量 |
| 合成 | composition | 固定快照到 Render IR，保留来源与时间语义 |
| 契约 | contracts、api-contracts、media-contracts、job-contracts、job-execution | 公共消息、错误、任务和端口数据 |
| 应用 | editor-application | 权限、用例、事务、幂等和资源政策 |
| 分派 | automation | 注册表驱动的类型化工具与领域动作 |
| 宿主 | host-runtime | 原生存储、媒体、插件与 Worker 装配 |
| 存储 | sqlite-store、asset-store、storage-budget | SQLite、CAS、准入、发布日志和回收围栏 |
| 媒体 | media、native-services、project-render、renderer | 探测、分析、IR 执行、原生 GPU 与受限子进程 |
| 调度与插件 | job-runtime、plugin-host | 领取、租约、取消、恢复、隔离和发布 |
| 客户端 | sdk-rust、sdk-ts、apps/web | 输入、呈现、传输与观察 |

领域、时间和合成层不读取 SQL、文件系统、网络或宿主环境。应用依赖契约与端口，宿主创建具体实现。内部调用不绕到 CLI；公开 DTO 不泄漏私有路径，客户端不复制领域规则。

工程修改基于固定修订，先计划、后原子提交。幂等键绑定原始请求，未知结果使用原键恢复。Worker 的 attempt、lease、取消和 publication fence 决定能否发布，临时文件不代表成功。

浏览器执行包消费 Rust 提供的固定事实与授权资源，不重新推导工程时间线。解码、DSP 和 GPU 保持准确的依赖身份。缓存、队列、PCM、RGBA 与子进程各自受准入约束，源文件大小与驻留预算分别处理。

静态帧、导出及连续 Web 预览的画面执行已接入独立 `opencut-render-worker`：原生 libav 通过授权字节端口解码，`renderer` 适配器执行固定 WGSL 和原生文字/图形栅格化，应用会话继续核验绑定、预算、取消和输出。父进程拥有二进制管道、RSS/期限监测和发布围栏。文字编辑和字幕规划通过同一受限进程协议使用共用的 CPU 布局，不创建设备或整张画布；其执行身份独立描述实际字体平台与栅格库，不虚构 GPU 身份。音频导出同样使用隔离原生执行，实时音频和来源图已完成硬切换及限定独立 PCM/像素验收；后续压缩音频定位、长时间预览与完整交付验收尚未完成；当前接线及其验收范围见[原生渲染方案](native-rendering.md)和[交付状态](status.md)。

现有工程的格式读取、SQL 升级和共享渲染器继续支持已保存的数据。第三方 WGSL、SoundTouch、字体和图形的许可证及来源哈希属于必要运行和分发数据。

历史工程包的画面编辑日志由同一 `ArchivedJournal::HistoricalVisualApply` 保存其原始形状：既有裸请求仍按裸请求序列化，原写入器的 `project_v3.apply` 包装保留原标记和嵌套请求。私有精确读取器按存储标记选择形状，拒绝未知标记及任一层的额外字段；作用域核验、原内核效果验证及导入时身份映射继续共用原实现。此修复只补齐原已存在的存储形状，不新增写入口、执行方式、公开 DTO、依赖或数据迁移，也不重写任何历史证明。

依赖准入以[审核基线](../design/architecture/dependency-policy.json)为准。静态门禁不代替行为及独立像素/PCM 验收。

执行检查点在单条 SQL 中读取当前凭证/授权、工程删除状态及可选固定修订存在性，再按原 Read、工程可见性、RunJobs、工程可见性的顺序调用共享应用策略。授权行仅活在本次检查点内，不跨调用缓存；每次检查仍使用新读事务，并完整解码全部授权行，保持撤权、删除及损坏授权数据的拒绝顺序。普通编辑权限入口不变。作业输入缓存中的当前策略改为完整类型化的音频/画面/视频策略事实，逐字段相等时避免重复生成 JSON；首次或变化时仍使用原完整 JSON 及历史兼容性核验。租约、取消、修订、原始输入 TEXT 和授权仍每次重新读取。这些 SQLite 内部调整不新增模块、依赖、公开 DTO 或数据迁移。

导出分辨率复用合成层的纯栅格投影：先按原工程时间和动画采样 IR，再投影画布像素坐标、文字及效果尺寸。来源资源、时钟、工程及固定修订不变；宿主按投影后的帧执行原准入和原生渲染。预览保持原 540p 规则，导出使用共享 Rust `RasterResolution` 显式尺寸，Web 只选择和提交枚举，不复制画布计算。旧请求缺省值和旧证明保持原尺寸；不新增操作、后端、模块或依赖边。

发行装配的 `scripts/distribution/native_runtime.py` 只处理可信构建输入、Mach-O 依赖闭包、分发副本的相对加载路径与许可证/对应源码；不引入领域操作、公共 DTO 或 Rust 依赖。CLI 与原生 worker 相邻，五个已进入执行身份的 FFmpeg 动态库位于 `bin/lib`；额外解码实现须静态纳入这些库，不能留下未进入身份的第三方动态库。系统框架仍由平台身份描述。新辅助运行时清单允许独立 FFmpeg/ffprobe 工具、Node 目录解包和 Python 字体派生，不装配浏览器渲染模块；历史清单继续精确读取。FFmpeg/ffprobe 组件必须携带并声明对应源码与构建记录；独立 GPL 编码工具不链接到 LGPL 原生解码 worker。宿主私有 `media_tool_runtime` 统一选择显式环境配置、完整性校验后的包内工具及未声明组件时的 PATH 工具；损坏清单或无效显式配置直接失败。原生目录音效、项目包工具指纹、旧预览和质量测量通过注入的工厂取得同一后端，保留原有授权、输入校验与错误分类时点。该模块只负责宿主装配，不新增依赖、公共 DTO 或业务操作。装配检查和原生启动探针不代替独立画面/PCM、项目及迁移安装验收。

字体派生证明绑定 `scripts/font-catalog/generate.py` 的完整原始字节；该文件作为不可变校验依赖保留，来源与哈希记录在 `static-validator-source.json`。当前目录发布入口是 `generate_catalog.py`，只维护当前 Rust 名称、目录和 atlas 路径，导入同一份校验/选择函数；运行时不执行冻结依赖中的历史发布命令。此拆分修复维护路径变化造成的身份漂移，不修改字体锁、保存的证明或字体字节，也不增加业务操作或依赖豁免。

Web 画面适配器消费公开原生帧和有界 RGBA 传输，显示工作器只呈现完成的像素。精确脚本门禁禁止 Web 导入旧 GPU 合成和原生宿主，仅允许画面适配器取得既有派生成品片段解码器；这条客户端装配边界不新增领域依赖或修改审核依赖基线。

画面准备的 HTTP 数据面在同一请求内调用原场景或编辑草稿用例，再领取其一次性像素；工具入口仍调用相同用例。Rust 公布严格类型的请求、准备帧头和传输事实，SDK/OpenAPI 由同一显式 CLI 生成。响应先发送 12 字节 `OCVP` 前缀（标记、little-endian JSON 长度、RGBA 长度），再发送最多 2 MiB 的原完整帧信息和原 straight RGBA8。领取先于任何响应内容；头信息和像素共用原 64 KiB 检查点、两个槽、一秒背压及当前凭证/会话围栏。Web 使用此单请求数据面；既有工具及独立读取仍供其他客户端使用，不加入回退链。此传输组合不增加业务操作、模块、依赖或审核基线例外。

连续预览的客户端流水线将已准备帧事实、读取者领取和完成像素分开：SDK 仅在成功的作用域响应及完整有效的已领取帧头之后返回准备事实，生产者随后才提交下一个原生意图。最多两项未完成读取，原六帧生产队列及 64 MiB 双副本预留继续生效；未完整校验长度、SHA-256 和位图尺寸的像素不能发给呈现工作器。停止会中断领取/容量等待并关闭已完成及晚到的位图。SDK 准备阶段不授予呈现信用，不更改宿主的逐块授权、代次或已领取内存计费；缓存和普通完整帧调用仍共用原有执行语义，不引入渲染后端、领域操作、模块或依赖。

宿主画面像素在最终授权/会话状态复核前计算 SHA-256，计算及等待期间仍持有原有内存预留；未通过围栏的准备像素不可领取，丢弃时释放全部预留。最终发布仍在会话状态锁内进行，哈希计算不占用音频消费所需的锁。宿主新增对锁中已有精确 `ring 0.17.14` 的直接依赖，仅用于这个传输摘要，不引入领域/应用依赖或另一套业务入口；保留的完整像素独立摘要与原 sha2 相同，960×540 样本局部测量显示加速实现减少摘要开销。审核基线只手工增加该宿主边；其它摘要继续原实现。若现有摘要依赖在支持的平台上提供同等吞吐并通过同一独立向量，可统一实现并移除这条直接依赖，不保留双路径选择。

HTTP 画面传输保持两个 64 KiB 槽和原一秒背压期限，等待队列容量通过运行时通知唤醒；等待超过 10 ms 时继续复核授权/代次，取得槽位后、发送前再次复核。释放容量不再强制等待完整 10 ms tick。原生 worker 的内部 GPU 上传复制原已只检查本地期限，不存在逐块宿主 RPC；没有为该假设修改 renderer 或 worker。

画面读取会话最多保留两条空闲 SQLite 读连接，可在同一会话的连续画面及定位之间复用；实际读取独占借出的连接，打开和查询在音频状态锁及池锁外进行，归还只短暂持有池锁。会话过期、停止，或维护线程因空闲/撤权/代次变化退休画面 owner 时，清空池并替换私有身份令牌，旧借用归还不能重新填入已退休的池。传输恢复已验证的 reader 先执行复制前后授权复核、再等待容量并在发送前复核的顺序；不将借出的 mpsc 槽位带入 SQLite 读取。背压等待期间仍按原 10 ms 上界复核并保留一秒期限。每个有序块仍进行原有权限、固定修订、owner/lease/generation/overlay 复核；只复用连接和编译后的 SQL，不缓存许可、查询行或跨检查点的读事务。预览修订存在性、凭证有效性和授权列表与既有作业/删除状态查询一样使用连接内 statement cache；每次绑定当前参数并读取当前数据库快照。此宿主/存储内部资源复用不新增模块、依赖或公开合同，保持原有应用授权规则和错误分类。

原生 GPU 工作纹理使用 `rgba8unorm`，执行身份从实际渲染器取得该格式；已存 `bgra8unorm` 证明保持精确读取。对齐的读回行直接借用映射内存，非对齐行使用一个 64 KiB 缓冲去除 padding，不再逐像素转换通道。两条路径仍在每个有序输出块前检查执行状态。编码器在每块写入前及每次背压等待或系统调用中断后复核授权、取消和预算，成功的非阻塞部分写入不重复完整复核；传输上限、任务期限和发布围栏不变。此内部适配器修改不增加依赖、公开 DTO 或执行方式选择。

来源上传使用随执行布局保留的 `MAP_WRITE | COPY_SRC` staging 缓冲；每个独立来源在一帧内占有独立槽，同一帧的重复引用共享已上传纹理。每次使用完整覆写有效像素，映射等待与有界复制继续检查执行期限；帧完成后才允许下一次映射。布局包含本帧来源尺寸及数量，变化时先释放旧 scratch，执行失败时退休所有 scratch，不能跨布局积累。CPU/GPU 准入分别包含实际 256 字节行距的 staging、来源纹理与读回；温帧不免除准入。这是原生适配器内的分配复用，不增加依赖或改变源颜色、方向、效果和公开操作。

原生 GPU 的来源纹理与 staging 共用现有布局槽，按来源尺寸及独立数量准入；每次完整覆写后才提交，同帧独立来源不共享槽，相同引用仍共用一次上传。帧结束后保留的纹理继续包含在原来源 GPU 字节预算中，布局变化先释放旧存储，执行失败及 owner 退休一并释放。映射等待改用原生设备完成事件，单次请求的等待期限取一毫秒与剩余期限的较小值，超时仅表示本次等待未完成；下一次等待前继续原检查点。真实设备错误、取消和期限仍退休执行器，未完成映射不能读写像素。此适配器内部变更不改着色器、公共合同、依赖或预算，不新增渲染入口。

`media/native_decode/scaler` 是媒体适配器的私有模块，拥有固定初始化参数的 libswscale 上下文及同步输出借用，不读取路径、工程或授权。转换继续使用 BILINEAR/ACCURATE_RND、原矩阵/范围和原未声明色度位置；帧接口只启用有界并行，不启用按帧元数据自动调色。线程数由像素数和当前驻留余量确定，最多四个，每个额外线程保守预留一张 RGBA 面及 2 MiB 的过滤/栈空间。输出用不转移 Rust 所有权的 AVBufferRef 包装；调用完成并清除所有切片引用后才结束借用，不增加整帧副本。上下文尺寸或并行度改变时先释放旧上下文；父进程继续对编解码器私有分配执行 RSS/期限监测。这一拆分隔离 FFI 所有权及 CPU 资源计算，不增加依赖、公开 DTO 或业务入口。

原生连续预览由其拥有者在私有进程协议中标记预览用途，视频颜色转换直接适配已准备画布的边界，保持比例且不放大来源；图片与导出仍转换原始尺寸。解码帧分别保存实际来源尺寸和传输像素尺寸，应用绑定、布局及背景比例使用来源尺寸，GPU 上传使用传输尺寸；PTS、时长、方向、颜色事实及授权字节来源不变。转换缓存同时匹配 PTS、时长和输出尺寸，同一解码器从预览尺寸切回原尺寸必须重新转换。编解码器参考面、额外线程及保留的 RGBA 继续计入原预算。此优化只前移预览转换尺寸，不创建素材代理、不改变导出资源选择，也不新增模块、依赖、公共合同或执行后端。

原生画面的相邻资源解析/解码准入及绑定回调使用私有有界批次传输，最多 96 项，覆盖原 32 个来源和 60 个媒体层；仍逐项调用同一类型化应用会话，在每项前后重新核验。父进程先完整反序列化批次，再按原顺序执行，失败后不执行或发送后续项；逐项发送回复，worker 立即解析为原绑定事实，不聚合所有回复 JSON。每个请求/回复保留原 2 MiB 元数据上限，较大批次按实际序列化长度拆包，单项保留原包络；64 KiB 来源/像素块及每帧 200,000 个逻辑请求上限保持，批次不能绕过计数。所有解码准入先于像素解码，完整绑定仍先于渲染和输出，原收据及发布围栏不变。这只减少原生适配器进程往返，不增加应用用例、公开 DTO、依赖或后端选择。

原生视频解码器保留最多一张前次 RGBA 转换面，下一次转换只在 `Arc` 唯一持有且字节长度相同时原地复用其缓冲；仍被调用方持有的旧帧不可覆写。原像素/颜色转换完整覆盖输出，不跳过转换、降低尺寸或更改舍入。缓存命中必须匹配实际 PTS 和时长，seek、已准入操作失败及退休释放解码器持有的转换面；操作前拒绝权限不暴露或读取缓存，不扩大原退休规则。格式变化分配前先放弃解码器对不适用旧面的持有。解码准入和并行转换余量计算包括保留的输出大小，不增加第二张空闲整帧面或放宽 RSS/驻留限额。

场景解码的工作面数量是纯执行 IR 的事实，不访问设备或文件：旧窄帧路径保持四工作面，画布传输使用两工作面；颜色背景的场景允许视频直接传递 VideoFrame，图片仍保留两工作面。应用按素材种类计算准入，前台 128 MiB、导出 224 MiB 的 RGBA 预算及 512 MiB GPU 限额保持原值。字幕重排必须证明媒体图没有变化，并保留原媒体传输合同，不能在重新准备文字时重置到窄帧默认值。

`classic-visual-renderer/src/legacy-color.mjs` 是宿主渲染适配器内的自有源码，负责源空间的保留调色与直接视频帧的方向处理；不引入领域依赖、第三方着色器替换或新业务入口。调色发生在放置和不透明度之前。保留调色的视频输入目前要求明确的有限范围 BT.601/BT.709 色彩元数据；超出支持范围明确拒绝。该自有 WGSL 包含在模块身份中，完整验收还绑定原生程序、Node、浏览器、解码器与着色器身份。

原生采样率的单/双声道 RIFF signed16 与 float32 PCM 共用已有的格式核验和分窗解码。保留短输入的 Web Audio 行为；长输入由原生观察事实准入，避免旧工程缺少声道元数据时按 64 声道分配而拒绝实际双声道数据。预算、整段母带连续状态和固定来源授权保持不变。直接 BT.709 视频帧上传产生的 sRGB 传递函数转换在源空间调色前恢复，只执行一次；画布和其它传递函数沿用原路径。

持续视频的 RGBA 输出沿用单帧处理器的 64 KiB 有序块与原生确认，最多 16 块合并一次浏览器往返，暂存显式计入预算；不通过整帧 POST/Blob 或请求体诊断复制整帧。编码后的 AVC 预览仍使用已有输出能力。PCM 准入与持久证明共用采样字节宽度声明，float32 证明的帧数按每声道四字节上界验证，旧 signed16 证明的两字节上界不变。

持续视频的私有浏览器到 Node 桥接使用规范 Base64，Node 逐块还原为原生十六进制包并调用同一处理器。批次固定原帧身份，不能跨帧重新标记；块大小、确认、预算与 Rust 输出协议保持不变。共享源解码器保留短距离连续迭代，超过已观察帧末端两秒的前跳重新定位同一 Input。缩略图队列对新可见内容给予有限优先级，最多三个前台加载后服务一个等待中的授权复核。测量与尚未解决的问题见[性能排查](performance.md)。

原生视频解码按已探测尺寸、像素格式、codec frame-thread 能力及现有驻留额度选择一至四个线程；小来源及不足余量保持单线程；容器未声明像素格式时，先取得一张通过准入的真实帧，再按已观察格式选择并行度，至多重开一次解码器并重新定位原请求。探测帧不发布，字节和包计数不重置，重定位仅使用本次操作剩余 I/O 额度。每个额外线程保守预留两张来源面和 2 MiB 的栈/私有状态，收到实际帧时按其格式和尺寸重新计账，再将剩余额度交给颜色转换。解复用与授权字节回调仍只在调用线程执行，codec 线程只处理已读取的数据；原 PTS、关键帧定位、排空、取消/撤权检查及父进程 RSS/期限监测保留。此适配器内部变更不新增模块、依赖、公开合同或业务入口，不改变原始素材、540p 预览和导出栅格选择。

原生音视频解码共用媒体适配器内的轨道选择规则：显式编号仍指物理流；缺省读取时，ISO BMFF 和 Matroska 依照保留解复用器的稳定顺序优先默认轨，其余容器保持原存储顺序，不按 codec、分辨率或语言另选“最佳”流。选择在同一已授权 AVIO 打开之后进行，不增加路径、探测解码、来源副本、应用操作、公开 DTO 或依赖；来源图、实时音视频与导出继续消费同一解码器。

原生素材预览派生的新增模块边界：`contracts::source_preview` 只声明来源、栅格、原片/代理双时钟和执行身份事实；`job-contracts::source_preview` 注册同一持久作业，`job-execution::source_preview` 保存宿主捕获的固定快照、权限及预算；`editor-application::source_preview` 负责准备、幂等身份、结果及帧索引验证，不进行 I/O。SQLite 适配器负责原子接受、当前授权和完成/发布围栏；原生适配器通过已有受限进程及授权字节端口解码，经既有编码器生命周期生成可核验的预览派生，宿主装配资源和进程。FFV1 保留 RGBA，原片 PTS/时长与代理容器时钟使用独立索引，来源几何/方向每帧保留。预览使用同一 Rust 合成器选择已验证来源；原片导出不查询派生来源。新增模块不创建领域依赖、CLI 内部 RPC、另一套编辑操作或新外部依赖，不修改准入基线以绕过门禁；当前集成仍以状态文档为准。

素材预览运行时身份先以完整文件散列捕获，再在每次准入检查宿主、worker、编解码库和工具的路径、inode、大小、修改及变更时间；仅依赖观察变化才重新捕获，避免定时完整散列阻塞前台。来源任务的实际身份、私有工作进程始末文件核验及逐块当前授权不变。FFV1 使用无损 Golomb/context0、单帧 GOP 与切片 CRC；无旋转 RGBA 按行复制，旋转及透明像素仍使用同一可逆映射及原检查点。没有新模块、依赖、合同或预算。

私有输出检查仍在每个既有检查点核验规范目录名和持有的 inode。macOS 通过已有 `rustix::fs::getpath` 取得目录描述符的当前名称；仅名称及新读取的命名/持有 inode 都相同时免除重复 `realpath` 遍历。名称、inode 不符或内核查询不可用时继续原规范路径检查，保留别名拒绝及原查找错误；其他平台继续原实现。目录名称和 inode 不缓存，授权、取消、作业输入、租约、期限及发布围栏仍逐次核验。此优化属于既有存储适配器，宿主只调用同一 `AttemptLease` 目录检查；不新增模块、依赖、公开 DTO、业务操作或预算豁免。内核接口用于取得持有目录的当前路径，符合 [Apple 文件系统指南](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html)的目录移动处理方式。
